# 색션 5 : 개발 환경 및 스프링

## 스프링 부트 프로젝트 환경 설정

### 프로젝트 생성 (start.spring.io)
* **Project** : 빌드 도구 선택 (Gradle 또는 Maven)
* **Language** : 개발 언어 선택
* **Packaging** : 배포 단위 설정
  * **Jar** : 웹 서버를 내장하여 실행 가능(권장)
  * **War** : 웹 서버 별도 필요
* **Dependencies** : 프로젝트에 필요한 라이브러리/기능 추가

### 프로젝트 구조 주요 요소
* **src/main/java** : 실제 소스 코드(Main 메소드 포함)
* **src/main/resources** : 설정 파일(application.properties) 등 비소스 파일
* **build.gradle** : 프로젝트 의존성 및 빌드 설정 관리 파일
* **External Libraries** : 프로젝트에 포함된 외부 라이브러리 목록

### 실행 방법
main 메소드가 포함된 클래스(Application)를 실행하여 서버가 정상적으로 구동되는지 먼저 확인하는 습관이 중요함.

# 색션 6 : 스프링의 핵심 원리

## 자바 개발의 문제점
스프링은 객체 지향 프로그래밍의 장점을 극대화하면서, 동시에 개발자가 겪는 '객체 관리의 번거로움'을 제거하기 위해 탄생함.

## 스프링의 주요 원리
### IoC
* Inversion of Control, 제어의 역전
* 기존의 자바 프로그래밍에서는 개발자가 객체를 직접 생성하고, 호출 순서를 제어함. IoC는 이 주도권을 프레임워크(스프링)에게 넘기는 것.
* 개발자는 '어떻게 비즈니스 로직을 구현할까'에만 집중

### 컨테이너와 스프링 빈
* **컨테이너** : 객체들을 관리하는 '거대한 박스'
  * 스프링 애플리케이션이 시작될 때 컨테이너가 생성됨.
  * 필요한 객체들을 미리 생성하여 담아둠.
* **스프링 빈** : 컨테이너가 직접 생성하고 관리하는 객체들
  * 일반적인 자바 객체(POJO)와 같지만, 스프링 컨테이너에 의해 생명주기가 관리됨.

### DI
* Dependency Injection, 의존성 주입
* **의존성이란?** :  A라는 클래스가 B라는 클래스의 기능을 사용한다면, A는 B에 '의존'한다 표현.
* **주입 방식** : 생성자나 설정 파일을 통해 스프링 컨테이너가 컨테이너 내부에 있는 B 객체를 찾아서 A에게 주입함.
