# 색션 6 : 클래스 설계 규칙과 어노테이션

## 프로젝트 개요
* **프로젝트명:** 상품 조회/등록 API 프로젝트
* **핵심 질문:** 어떤 클래스를 만들어야 할까?
* **기술 스택 설정:** Spring Initializr -> Spring Web (Sprint MVC)

## Spring MVC 패턴 개요

### 클래스 구조와 역할 부여
Spring MVC 패턴은 각 클래스에 명확한 역할을 부여하여 애플리케이션의 결합도를 낮추고 유지보수성을 향상시킴.

* **View:** 사용자에게 보여지는 화면 영역.
* **Controller:** 사용자의 요청(Request)을 받아들이는 View와 비즈니스 로직(Model) 사이의 중간 매개체 역할을 함.
* **Model:** 데이터 연산 및 핵심 비즈니스 로직 담당
  * **상세 역할 분리:** 유지보수를 용이하게 하기 위해 데이터베이스와의 소통 및 비즈니스 로직을 `Repository`와 `Service`로 상세히 분리하여 관리.
  
### 개발 순서
보편적으로 흐름을 먼저 잡기 위해 요청을 직접 맞이하는 계층부터 순차적으로 제작합니다.
1. **Controller 선 제작:** 외부 요청을 가장 먼저 받으므로 우선적으로 구조를 잡음.
2. **Model 후 제작:** Controller의 요청을 받아 실제 비즈니스 로직과 데이터 처리를 수행하는 클래스들을 뒤이어 제작함.

## 클래스 제작 및 스프링 어노테이션

### 클래스 제작 규칙
* **명확한 네이밍:** Java Class를 제작할 때 단순히 `"Controller"`처럼 추상적인 이름보다는, **구체적인 역할과 도메인이 명시되는 이름**으로 작성해야 함. (예: `ProductController` 등)
* **스프링 빈(Spring Bean) 등록:** 스프링 프레임워크에게 *"이 클래스를 기반으로 객체(컴포넌트)를 알아서 잘 생성하고 관리해줘"*라고 명시해야 합니다.
  * **전달 방법:** **어노테이션(Annotation)**을 활용합니다.

### 어노테이션 (Annotation) 개념 정리
자바 소스 코드에 추가하여 메타데이터를 제공하는 기능으로, 정보를 **"알려주는" 역할**을 수행합니다. 주체에 따라 다음과 같이 구분할 수 있습니다.

1. **컴파일러에게 알려주기**
   * 문법적 오류를 체크하도록 지시합니다.
   * *예시:* `@Override` (부모 클래스의 메서드를 올바르게 재정의했는지 컴파일 시점에 체크 요청)
2. **빌드 도구에게 알려주기**
   * 반복적인 코드를 자동으로 생성하도록 지시합니다.
   * *예시:* `@Getter`, `@Setter` (Lombok 라이브러리를 통해 빌드 시점에 Getter/Setter 메서드 자동 생성)
3. **프레임워크에게 알려주기**
   * 스프링 컨테이너가 해당 클래스의 생명주기를 직접 관리하도록 지시합니다.
   * *예시:* *"스프링아.. 나 아래 클래스를 스프링 빈으로 등록할 테니까 네가 좀 관리해 줘"* (`@Controller`, `@Service`, `@Repository` 등)
