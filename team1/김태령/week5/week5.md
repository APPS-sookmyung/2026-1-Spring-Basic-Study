#Spring-Basic-Week5

## 클래스 구조 (= 역할 분리)
* Spring MVC는 역할을 나누어 개발하는 구조
### View
* 사용자에게 보여지는 화면
* 사용자에게 입력을 받음
### Controller
* View와 Model 사이의 중간 관리자 역할
* 사용자의 요청을 받아 처리 및 필요한 Model을 호출
* 결과를 다시 View로 전달
### Model
* 실제 비즈니스 로직과 데이터 처리 담당
* 내부에서 역할이 분리되는데 Service가 비즈니스 로직을 처리하고 Repository가 DB 접근을 담당

## Controller 만들기
* Controller는 사용자의 요청을 받아 처리하는 클래스
* 스프링에서는 @Controller 어노테이션을 사용

## 스프링에게 말을 거는 방법 = 어노테이션
* 코드에 추가 정보를 제공하는 문법
* 이 코드는 이런 역할이라고 컴파일러나 프레임워크에게 알려주는 표식

## 어노테이션의 역할
### 1. 컴파일러에게 정보 제공 (@Override)
* 부모 클래스의 메서드를 재정의 했다는 뜻
* 오타나 잘못된 메서드 선언을 컴파일 단계에서 검사 가능
### 2. 빌드 도구에게 정보 제공 (@Getter)
* Getter/Setter 코드를 자동 생성
* 반복 코드를 줄여줌
### 3. 프레임워크(Spring)에게 정보 제공
* 객체 생성, 메모리 관리, 의존성 주입 등을 스프링이 대신 처리
