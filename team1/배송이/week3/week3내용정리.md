# Spring Boot 입문과 API 개념 정리

웹 개발 초창기에는 프론트엔드와 백엔드의 구분이 지금처럼 명확하지 않았다. 화면을 보여주는 부분과 데이터 처리 로직이 한곳에 섞여 있었기 때문에 기능이 많아질수록 유지보수가 어려워지고 복잡도가 크게 증가했다. 사용자와의 상호작용이 많아지고 서비스 규모가 커지면서 자연스럽게 역할 분리가 필요해졌다.

프론트엔드는 사용자가 직접 보는 화면과 UI를 담당하고, 백엔드는 데이터 처리와 시스템 로직을 담당한다. 예를 들어 로그인 화면이나 버튼 클릭 같은 것은 프론트엔드의 영역이고, 회원 정보 저장이나 게시글 등록, 데이터베이스 관리 같은 것은 백엔드의 역할이다. 특히 백엔드 개발자는 API를 만드는 일을 중요하게 담당한다.

API는 Application Programming Interface의 줄임말로, 다른 시스템이나 프론트엔드가 백엔드의 기능이나 데이터에 접근할 수 있도록 만들어 둔 통로라고 이해하면 쉽다. 만약 사용자가 데이터베이스에 직접 접근하게 된다면 보안 문제도 크고 사용 방법도 너무 복잡해진다. 그래서 API를 통해 내부 구조를 숨기고, 필요한 데이터만 안전하게 제공하는 방식이 사용된다. 결국 API는 시스템의 안정성과 보안을 지켜주는 중요한 인터페이스다.

REST API는 HTTP의 규칙을 잘 지키면서 설계된 API를 의미한다. 여기서 RESTful API는 그 원칙을 더 엄격하게 잘 지킨 경우를 말한다. 쉽게 말하면 REST API는 규칙을 잘 지킨 API이고, RESTful API는 정말 깔끔하게 잘 지킨 API라고 생각하면 된다.

Spring Boot 프로젝트는 보통 Spring Initializr 에서 시작한다. 여기서 Project는 빌드 도구를 의미하는데 보통 Gradle-Groovy를 많이 사용한다. Build란 작성한 코드가 실제로 실행될 수 있도록 컴파일하고 패키징하는 전체 과정을 말한다. Language는 Java를 선택하고, Spring Boot 버전은 너무 최신보다는 안정적인 버전을 선택하는 것이 좋다.

Packaging에서는 Jar를 가장 많이 사용한다. Jar는 웹 서버까지 함께 포함해서 하나의 파일로 실행할 수 있기 때문에 배포가 훨씬 편하다. Java 버전은 보통 17을 많이 사용하며, Spring Boot 3.x부터는 Java 17 이상이 필요하다. Dependencies에서는 Spring Web을 추가하는데, 이것이 웹 서버 실행과 API 개발의 핵심 역할을 한다.

프로젝트를 생성하고 나면 가장 먼저 DemoApplication.java를 실행해보는 습관이 중요하다. main 메소드가 있는 이 파일이 프로젝트의 시작점이며, 실행 후 콘솔에 Started DemoApplication이 보이면 정상적으로 실행된 것이다.

Spring의 핵심은 객체를 관리하는 방식에 있다. Java는 객체지향 언어이기 때문에 객체를 언제 만들고 어디서 관리할지가 굉장히 중요하다. 이를 해결하기 위해 Spring은 IoC와 DI라는 개념을 사용한다. IoC는 제어의 역전으로, 개발자가 직접 객체를 관리하던 것을 Spring에게 맡기는 것이다. Spring은 객체를 컨테이너 안에서 관리하고, 이렇게 관리되는 객체를 Bean이라고 부른다.

DI는 Dependency Injection, 즉 의존성 주입이다. 개발자가 직접 객체를 만드는 것이 아니라 Spring이 객체를 생성해서 필요한 곳에 넣어주는 방식이다. 결국 IoC를 구현하기 위해 DI가 필요하다는 것이 가장 중요한 핵심이다. Spring은 복잡한 객체 관리를 대신 해주는 프레임워크라고 이해하면 훨씬 쉽게 접근할 수 있다.
