# Spring MVC와 어노테이션 정리

## Spring MVC 구조

Spring MVC는 프로그램을 역할별로 나누어서 개발하는 방식이다.  
각 부분이 담당하는 역할을 분리하면 코드가 복잡해지는 것을 줄일 수 있고, 수정이나 유지보수도 쉬워진다.

Spring MVC는 크게 View, Controller, Model로 구성된다.

---

## View
View는 사용자에게 보여지는 화면이다.  
사용자는 화면을 통해 정보를 입력하거나 결과를 확인한다.

예를 들어 쇼핑몰 사이트에서 상품 목록 페이지나 로그인 화면이 View에 해당한다.

---

## Controller
Controller는 사용자의 요청을 가장 먼저 받는 역할을 한다.  
사용자가 어떤 기능을 요청하면 Controller가 이를 확인하고 필요한 작업을 처리하도록 연결해준다.

예를 들어 사용자가 “상품 조회” 버튼을 누르면 Controller가 요청을 받아 상품 데이터를 가져오도록 처리한다.

즉, View와 Model 사이를 이어주는 중간 관리자 역할이라고 볼 수 있다.

---

## Model
Model은 실제 데이터 처리와 비즈니스 로직을 담당한다.

보통 역할을 다시 나누어서 사용한다.

- Service : 핵심 기능과 로직 처리
- Repository : 데이터베이스(DB)와 연결

예를 들어 상품 정보를 조회하는 기능이라면:

- Controller → 조회 요청 전달
- Service → 상품 조회 로직 수행
- Repository → DB에서 상품 데이터 가져오기

이런 흐름으로 동작하게 된다.

---

# 어노테이션(Annotation)

어노테이션은 코드에 추가 정보를 표시하는 문법이다.  
스프링이나 컴파일러에게 “이 코드는 이런 역할을 한다”라고 알려주는 역할을 한다.

---

## 어노테이션의 역할

### 1. 컴파일러에게 알려주기
대표적으로 메서드 재정의를 검사할 때 사용된다.

부모 클래스의 메서드를 수정하려고 했는데 이름을 잘못 입력하면 오류를 알려준다.

즉, 오타나 잘못된 메서드 선언을 미리 확인할 수 있어서 실수를 줄이는 데 도움이 된다.

---

### 2. 빌드 도구에게 알려주기
반복적으로 작성해야 하는 코드를 자동 생성하도록 도와준다.

예를 들어 Getter 같은 메서드를 직접 작성하지 않아도 자동으로 만들어주는 기능이 있다.

이를 통해 코드 길이를 줄이고 개발 효율을 높일 수 있다.

---

### 3. 스프링에게 알려주기
스프링에서는 어노테이션을 사용해 객체를 관리한다.

예를 들어 Controller 역할을 하는 클래스에 어노테이션을 붙이면 스프링이 해당 객체를 자동으로 생성하고 관리해준다.

개발자는 객체를 직접 생성하지 않아도 되기 때문에 코드 관리가 편리해진다.

---

# 정리

- Spring MVC는 역할을 분리하여 개발하는 구조이다.
- View는 화면, Controller는 요청 처리, Model은 데이터와 로직을 담당한다.
- Model 내부에서도 Service와 Repository로 역할이 나뉜다.
- 어노테이션은 코드의 역할을 컴파일러, 빌드 도구, 스프링에게 알려주는 기능이다.
- 이를 통해 코드 관리와 유지보수가 쉬워진다.
